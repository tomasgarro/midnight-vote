## Product contract

Midnight Passport means the account and identity product. A physical passport is
an NFC-readable travel document and a later evidence provider. These names must
not be abbreviated into the same label in the interface.

The target is one action to vote, a durable on-chain ballot, automatic counting
after closing, and independent verification. An open poll admits any proven
Midnight Passport account once; this is not proof of one human. Nationality,
residence, age and membership are different claims. Restricted polls remain
unavailable without a genuine verifier for the exact claim.

Public, anonymous and private-total modes are all required before a real pilot.
Disclosure and eligibility are fixed at publication. No participant must return
for their vote to count. No trustee arrangement has been approved.

## Verified Midnight Passport capabilities

The full SDK remains planning/specification work. Its development was reset on
15 October. Do not confuse it with the small demo connector.

The official demo connector is vendored with its Apache-2.0 licence at commit
`d343acf6674b7258e04cad9eb5d64c054f0dfebd` (v5.2), package version 0.1.1.
It provides profile consent, payments and signed redirects. It has no arbitrary
message-signing, credential, scoped-grant, holder-binding or private-storage API.

The profile vocabulary is `displayName` and `passportContract`. The connector has
no network option, so the returned account network must be checked explicitly.
The current account target is Stagenet; the voting target is Preview.

A signed redirect verifies BIP-340 over the payload. Its optional signer-address
check binds to an unshielded wallet address, **not** to the account contract.
Therefore neither profile consent nor this signature authorizes voting or
organizer operations. Live write endpoints fail closed until independently
verified account control is available. Reconnect always requires fresh consent.

## Ballot and private-tally experiment

`polls` implements immutable publication rules, encrypted receipt recovery,
complete ordered ballot-set commitments, server-side challenge binding and
explicit verification stages. A receipt opening, chain inclusion and aggregate
proof are separate facts. Imported JSON is never canonical chain evidence.

The isolated encryption experiment uses hybrid RSA-OAEP/AES-GCM. Its processor
can decrypt individual choices, potentially before closing. It does **not**
implement a ZK aggregate proof and is not an approved production privacy model.

The bounded Compact prototype accepts up to 16 committed/encrypted ballots and
counts their openings in one batch after closing. Private local totals are
published once, preventing per-vote public counter deltas. The complete indexed
set is checked, so missing, reordered or modified openings fail. It remains a
research contract: it lacks genuine Midnight Passport admission and a proof
that the stored ciphertext can be decrypted to the committed opening. One
malicious encrypted opening could otherwise block counting. It must not be
deployed as a live poll.

Automatic delayed disclosure requires an explicit time/decryption/availability
model. Publishing plaintext choices during voting and merely hiding the totals
in the interface would not satisfy the agreed product. No mode may silently
weaken that promise.

Reference for the processor trust distinction:
https://maci.pse.dev/docs/introduction

## Remaining real-pilot gates

1. Verifiable control of Midnight Passport accounts, with replay, origin,
   network and purpose binding; an unlinkable per-poll admission scheme.
2. Full Ledger 9 transaction/provider/browser-proving integration, fresh
   deployed contracts, independent indexer confirmation and fee funding.
3. Automatic delayed disclosure for all modes; approved private-tally trust,
   ciphertext validity, key availability and independently checked aggregate proof.
4. Durable authenticated organizer service and canonical poll/ballot storage.
5. Complete three-mode live lifecycle and independent verifier, mobile proving
   measurements, monitoring and invited human pilot.

None of these gates may be marked complete merely because the demonstration UI
works or the contract simulator passes. Physical-passport NFC and mainnet follow
these gates, rather than replacing Midnight Passport in the core flow.
